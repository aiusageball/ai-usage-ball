# AI Usage Ball Promotion Content Queue

This queue is built around the product's strongest observable difference:
AI Usage Ball is a beautiful, glanceable macOS desktop widget for seeing how
much Claude, Codex / ChatGPT, and Antigravity usage is left and when it resets.

The goal is qualified downloads and useful feedback, not a higher impression
count by itself.

## Positioning

Use this as the working message in every owned channel:

> A beautiful, glanceable macOS widget for your AI coding quota.

Long version:

> AI Usage Ball keeps Claude, Codex / ChatGPT, and Antigravity usage and reset
> times visible as live liquid gauges while you work.

Do not use an absolute “only one on the market” claim in public copy. The
defensible version is:

> I haven't found another macOS widget that combines cross-tool remaining
> quota, reset times, and a visual liquid UI like this.

## Operating rules

- Owned social accounts can be scheduled through Buffer after the account is
  connected.
- Every post gets its own `ref` value. Do not reuse a source tag across posts.
- Use the real screenshot or screen recording. Do not show invented quota data
  as if it came from a user's account.
- The user-provided original screen recording is approved for direct use. The
  derived crop `docs/ai-usage-ball-x-demo.mp4` is not approved for publishing.
- Rewrite each post for its platform; never paste the same announcement into
  several communities.
- Reddit, Hacker News, and Product Hunt entries are drafts only until a human
  checks the current rules and submits them.
- Do not ask for upvotes, positive reviews, or shares in exchange for the
  founding-user offer. Ask for a product test and honest feedback.

## Four-week owned-channel queue

Initial cadence: three posts per week across the connected owned channels.
Buffer should publish the scheduled posts; a human or operator should review
replies and pause a queue if a post receives a support or privacy question.

## Community queue (human submission only)

These are not automatic Buffer posts.

1. `r/ChatGPTCoding`: use the newest weekly self-promotion thread, include
   what was built, the problem, supported tools, intended audience, and the
   specific feedback requested. Use `?ref=reddit_chatgptcoding`.
2. `r/macapps`: participate first, check the current karma and developer-post
   requirements, then submit one platform-native post with the visual demo.
   Use `?ref=reddit_macapps`.
3. Hacker News: submit a real `Show HN` only when someone is available to
   answer technical questions for several hours. Use `?ref=show_hn`.
4. Product Hunt: maintain the existing page with genuine replies. A future
   relaunch should wait for a significant product update and a suitable
   interval; do not buy a Hunter or ask for votes.

## Weekly review

Record these values by exact `ref` tag:

- visits and referrers in Cloudflare Web Analytics;
- standard `AI-Usage-Ball.dmg` download-count change in the GitHub release;
- completed app launches when observable;
- substantive feedback and the issue it reveals.

Do not count `latest.json` updater requests as installs. Pause or rewrite a
post that gets visits without downloads after enough exposure, and reuse only
the message/source combinations that produce a real download or useful
feedback.

## Handoff to an operator

If the goal is zero day-to-day posting work, invite a human indie-app
operator to Buffer with a separate login. Give them channel-level `Full
Posting` access only for owned social accounts, and keep Reddit, Hacker News,
and Product Hunt under a submit-and-review process. Remove access when the
engagement period ends; do not share the primary account password.
